## 各组件详细说明

### 1. STM32F1xx HAL Driver（BSD-3-Clause）

**来源**：STMicroelectronics 官方提供，随 STM32CubeMX 生成。

**许可证原文**（`Drivers/STM32F1xx_HAL_Driver/LICENSE.txt`）：

> This software component is provided to you as part of a software package and applicable license terms are in the Package_license file. If you received this software component outside of a package or without applicable license terms, the terms of the **BSD-3-Clause** license shall apply.

**本项目使用方式**：

- **直接使用，未修改**：`stm32f1xx_hal.c`、`stm32f1xx_hal_tim.c`、`stm32f1xx_hal_gpio.c`、`stm32f1xx_hal_uart.c` 等
- 通过 HAL API 完成外设配置与操作，例如：
  - `HAL_TIM_PWM_Start()` 启动 PWM 输出
  - `HAL_GPIO_ReadPin()` / `HAL_GPIO_WritePin()` 操作 GPIO
  - `HAL_UART_Init()` 配置串口
- **未修改 HAL 库源码的任何内容**

**遵守 BSD-3-Clause 的方式**：保留原始版权声明与 LICENSE 文件（`firmware/Drivers/STM32F1xx_HAL_Driver/LICENSE.txt`）。

### 2. CMSIS Core（Apache-2.0）

**来源**：ARM Limited 的 Cortex Microcontroller Software Interface Standard。

**许可证**：`Drivers/CMSIS/LICENSE.txt` 明确为 **Apache License Version 2.0**。

**本项目使用方式**：

- 通过 CMSIS 提供的宏访问内核寄存器，例如：
  - `__disable_irq()` 在 `Error_Handler()` 中关闭中断
  - `__HAL_RCC_*_CLK_ENABLE()` 使能外设时钟（实际是 CMSIS + HAL 的宏封装）
- 提供 `core_cm3.h` 中的 NVIC、SysTick 等内核外设访问
- **未修改 CMSIS 源码**

**遵守 Apache-2.0 的方式**：保留 LICENSE 文件与版权声明；未修改，无需额外声明修改记录。

### 3. CMSIS Device — STM32F1xx

**来源**：STMicroelectronics，包含 `stm32f103xb.h`（寄存器定义，842KB）、`system_stm32f1xx.c`（系统时钟初始化）、启动文件 `startup_stm32f103xb.s`。

**本项目使用方式**：

- 直接引用寄存器定义，例如 `USART1->SR`、`TIM2->CCR1`、`AFIO->MAPR` 等
- `SystemInit()` 在启动时调用
- **未修改**

### 4. STM32CubeMX 生成代码

**来源**：STMicroelectronics 的代码生成器。

**本项目中的文件**（由 CubeMX 生成，我们仅在 `USER CODE` 区块内添加自己的代码）：

| 文件 | 我们的修改 |
| --- | --- |
| `Core/Src/main.c` | 在 `USER CODE BEGIN/END` 区块内添加应用逻辑 |
| `Core/Src/tim.c` | **未修改**（仅使用生成的初始化） |
| `Core/Src/gpio.c` | **未修改** |
| `Core/Src/usart.c` | **未修改** |
| `Core/Src/stm32f1xx_it.c` | **未修改**（SysTick 中断调用 `HAL_IncTick()`） |
| `Core/Src/stm32f1xx_hal_msp.c` | **未修改** |
| `Core/Src/syscalls.c` / `sysmem.c` | **未修改** |

> **CubeMX 的 `USER CODE` 机制**：生成器只会保留 `/* USER CODE BEGIN xxx */` 与 `/* USER CODE END xxx */` 之间的内容，其余部分每次重新生成都会被覆盖。我们**严格遵守这个约定**，所有自写代码都放在 `USER CODE` 区块内，因此 `.ioc` 文件可随时重新生成而不丢失代码。

### 5. 塔克创新 PS2 手柄驱动（参考实现）

**来源**：塔克创新（XTARK）提供的 PS2 无线手柄参考程序，随手柄配套资料赠送。

**原始文件**：

- `Driver/ax_ps2.c`、`Driver/ax_ps2.h`（STM32F1 版）
- `User/main.c`（4WD 小车例程）

**⚠️ 本项目的做法：参考协议与时序逻辑，代码已完全重写。**

我们对照厂商代码理解了以下关键点（这些是硬件协议的客观事实，不属于代码著作权范围）：

| 项目 | 内容 |
| --- | --- |
| 引脚分配 | PA4=DAT、PA5=CMD、PA6=CS、PA7=CLK |
| 命令数组 | `{0x01, 0x42, 0x00, ..., 0x00}` 共 9 字节 |
| 位顺序 | LSB 先行 |
| 半周期延时 | 16µs |
| 采样时刻 | 时钟低电平期间读取 DAT |
| 取反约定 | `btn = ~data` 使"1 = 按下" |

**我们重写并新增的部分**：

| 项目 | 厂商原版 | 本项目 |
| --- | --- | --- |
| 文件组织 | `ax_ps2.c` + 独立 `ax_delay.c` | 合并进 `ps2.c`，延时内置 |
| 微秒延时 | `AX_Delayus()`（未知实现） | **TIM1 自由计数器**（1MHz，明确可靠） |
| 引脚定义 | `PAout(5)=1` 宏 | `HAL_GPIO_WritePin()` 标准 HAL 调用 |
| **数据校验** | **无** | **✅ 新增两层校验**（模式字节 + 0x5A 固定字节） |
| **掉线检测** | **无**（void 函数） | **✅ 返回 1/0**，调用方可判断数据有效性 |
| 取反类型转换 | `btn1 = ~PS2_data[3]`（隐式截断） | `(uint8_t)(~ps2_rx[3])`（显式，语义清晰） |
| 结构体 | `JOYSTICK_TypeDef` | `ps2_state_t`（重新命名并加注释） |

**为什么这样处理**：厂商代码是**硬件协议的参考实现**，而硬件协议（字节定义、时序要求）是客观事实，任何驱动都必须遵循。但具体代码组织、错误处理、接口设计由我们独立完成。

**遵守的方式**：在本文件（`docs/10`）中**完整说明参考来源与我们的改动**，满足竞赛手册"必须给出完整说明"的要求。

### 6. newlib / newlib-nano

**来源**：GNU Arm Embedded Toolchain 自带的 C 标准库。

**本项目使用方式**：

- `printf()` 用于串口调试输出
- **重定向 `_write()` 到 USART1**（覆盖 newlib 的弱符号）：

```c
int _write(int file, char *ptr, int len)
{
    (void)file;
    for (int i = 0; i < len; i++) {
        while (!(USART1->SR & USART_SR_TXE)) { }
        USART1->DR = (uint8_t)ptr[i];
    }
    while (!(USART1->SR & USART_SR_TC)) { }
    return len;
}
```

- **链接选项 `-u _printf_float`**：newlib-nano 默认不支持浮点格式化，加这个选项让 `%f` 可用

### 7. arm-none-eabi-gcc

**用途**：交叉编译生成 STM32 可执行文件。**仅作为工具使用**，其 GPL 许可证不传染到我们的代码（因为我们是链接其运行时库，而非修改编译器本身）。

### 8. CMake

**用途**：构建系统。项目由 STM32CubeMX 的 CMake 转换工具生成，我们仅添加了用户源文件与链接选项。

## 我们自己的原创代码

以下模块**完全由本队独立编写**，未参考任何外部实现：

| 文件 | 行数 | 内容 |
| --- | --- | --- |
| `Core/Src/motor.c` | 约 250 行 | 死区补偿算法、软启动斜坡、PWM 写入、H 桥控制 |
| `Core/Src/chassis.c` | 约 180 行 | **麦克纳姆轮逆运动学**、归一化、四轮降额、方向标定 |
| `Core/Src/ps2.c` | 约 200 行 | PS2 协议实现（参考厂商结构后重写）、两层数据校验、TIM1 微秒延时 |
| `Core/Src/main.c` 的应用逻辑 | 约 200 行 | 时间片调度、按键解析、急停状态机、死区补偿的调试验证 |
| `Core/Inc/motor.h` / `chassis.h` / `ps2.h` | — | 接口定义与参数说明 |

**核心技术亮点**（均独立推导实现）：

1. **马达静摩擦死区补偿算法**（`motor_deadzone_comp`）—— 从故障现象出发，通过实测定位根因，设计线性映射方案
2. **麦轮逆运动学 + 归一化**（`chassis_mecanum`）—— 标准公式的正确实现，含归一化保障方向不变形
3. **两层协议数据校验**（`PS2_Scan`）—— 比厂商参考实现更健壮
4. **软启动斜坡 + 影子变量同步机制**（`motor_set_ramp`）—— 含"绕过斜坡时必须清影子变量"的完整处理

详见 [04 电机驱动与PWM调速](./04-电机驱动与PWM调速.md)、[06 PS2手柄通信与遥控](./06-PS2手柄通信与遥控.md)、[05 麦克纳姆轮运动学解算](./05-麦克纳姆轮运动学解算.md)。
