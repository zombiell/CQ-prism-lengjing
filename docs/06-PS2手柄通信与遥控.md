# 04 PS2 手柄通信与遥控

> 对应中期考核指标 **6：底盘运动（单一）**、**7：底盘运动（全部）**

## 底盘运动（单一）

### 功能说明

使用 **PS2 无线手柄**控制机器人完成**单个方向的水平平移**（例如只按 ↑ 前进、只按 → 右移）。

### 实现链路

```
手柄按键
   ↓ 2.4GHz 无线
PS2 接收器
   ↓ 4 线同步串行（DATA/CMD/CS/CLK）
STM32 PA4/PA5/PA6/PA7
   ↓ ps2.c 软件模拟时序
g_ps2.btn1 / btn2（位掩码）
   ↓ main.c 按键解析
vx / vy / w（三个浮点量）
   ↓ chassis.c 麦轮逆运动学
四个轮子的 duty
   ↓ motor.c 死区补偿 + PWM
8 路 PWM 输出
```

### 按键 → 动作映射

| 手柄按键 | 代码判断 | 产生的意图 |
| --- | --- | --- |
| ↑ | `btn1 & PS2_BTN_UP` | `vx = +0.50`（向前） |
| ↓ | `btn1 & PS2_BTN_DOWN` | `vx = -0.50`（向后） |
| → | `btn1 & PS2_BTN_RIGHT` | `vy = +0.50`（向右） |
| ← | `btn1 & PS2_BTN_LEFT` | `vy = -0.50`（向左） |

```c
float vx = btn_to_float(g_ps2.btn1 & PS2_BTN_UP,    +MOVE_SPEED)
         + btn_to_float(g_ps2.btn1 & PS2_BTN_DOWN,  -MOVE_SPEED);
float vy = btn_to_float(g_ps2.btn1 & PS2_BTN_RIGHT, +MOVE_SPEED)
         + btn_to_float(g_ps2.btn1 & PS2_BTN_LEFT,  -MOVE_SPEED);
float w  = btn_to_float(g_ps2.btn2 & PS2_BTN_CIRCLE, +TURN_SPEED)
         + btn_to_float(g_ps2.btn2 & PS2_BTN_SQUARE, -TURN_SPEED);

chassis_mecanum(vx, vy, w);
```

其中：

```c
static float btn_to_float(uint8_t pressed, float value)
{
    return pressed ? value : 0.0f;      /* 三目运算符 */
}
```

### ⚠️ 关键限制：本手柄摇杆没有模拟量

塔克创新官方手册原文：

> **左右摇杆模拟值为无效，推到极限时，对应发送 UP、RIGHT、DOWN、LEFT、△、○、X、□，按键 L3、R3 无效。**

这意味着：

| 操作 | 手柄实际发送 | 本代码是否响应 |
| --- | --- | --- |
| **十字方向键 ↑** | byte4 的 UP 位 | ✅ 前进 |
| **左摇杆推到最上** | byte5 的 **△** 位 | ❌ **不响应** |
| 左摇杆推到最下 | byte5 的 **×** 位 | ❌ 不响应 |
| 左摇杆推左/右 | byte5 的 **□/○** 位 | ⚠️ 会被当作**原地自转** |

**因此必须使用十字方向键控制，推摇杆不会产生平移。**

摇杆的 4 个数据字节（`ps2_rx[5]~[8]`）在本手柄上是无效数据，代码中仅保存用于调试观察，**绝不参与控制** —— 否则会出现"手柄没动、车却一直冲"的危险现象。

## 底盘运动（全部）

### 功能说明

机器人能够完成**全向水平运动**，包括：

| 动作 | 按键 | vx | vy | w |
| --- | --- | --- | --- | --- |
| 前进 | ↑ | +0.5 | 0 | 0 |
| 后退 | ↓ | −0.5 | 0 | 0 |
| 右移 | → | 0 | +0.5 | 0 |
| 左移 | ← | 0 | −0.5 | 0 |
| 右前斜行 | ↑ + → | +0.5 | +0.5 | 0 |
| 左前斜行 | ↑ + ← | +0.5 | −0.5 | 0 |
| 右后斜行 | ↓ + → | −0.5 | +0.5 | 0 |
| 左后斜行 | ↓ + ← | −0.5 | −0.5 | 0 |
| 原地顺时针 | ○ | 0 | 0 | +0.5 |
| 原地逆时针 | □ | 0 | 0 | −0.5 |
| 边走边转 | 方向键 + ○/□ | 组合 | 组合 | 组合 |

### 为什么"相加"就能组合出 8 个方向

代码把两组相反方向的按键**相加**，而不是用 `switch` 判八方向：

- 只按 ↑ → `vx = 0.5 + 0 = +0.5`
- 只按 ↓ → `vx = 0 + (−0.5) = −0.5`
- 同按 ↑ 和 → → `vx = +0.5, vy = +0.5` → **自动斜行**
- 同按 ↑ 和 ↓ → `vx = 0.5 + (−0.5) = 0` → **自动停**，不需要额外判断

**优点**：3 行代码换来 8 个方向 + 自动处理矛盾输入，比 `switch` 判 8 种情况简洁得多。

## PS2 通信协议解析

### 物理层：4 根线

| 线 | 方向 | 作用 | STM32 引脚 |
| --- | --- | --- | --- |
| **CS / ATT** | STM32 → 接收器 | 片选，拉低表示开始通信 | PA6 |
| **CLK** | STM32 → 接收器 | 时钟，主机产生 | PA7 |
| **CMD** | STM32 → 接收器 | 命令数据 | PA5 |
| **DATA** | 接收器 → STM32 | 手柄数据 | PA4（上拉输入） |

**这是"主机同步串行"模式**：时钟完全由 STM32 主导，接收器是被动从机。收发同时进行，属于**全双工**。

### 数据帧：9 个字节

| 字节 | 发送（命令） | 接收（数据） | 含义 |
| --- | --- | --- | --- |
| 0 | 0x01 | 0x01 | 起始字节 |
| 1 | 0x42 | **0x73** | 查询命令 / 手柄模式（0x41 数字、0x23 NegCon、0x73 工作模式） |
| 2 | 0x00 | **0x5A** | 小振动强度 / **固定标志位"数据来了"** |
| 3 | 0x00 | data | 大振动强度 / **按键组 1** |
| 4 | 0x00 | data | **按键组 2** |
| 5 | 0x00 | data | 右摇杆 左右（0x00 左 ~ 0xFF 右） |
| 6 | 0x00 | data | 右摇杆 上下 |
| 7 | 0x00 | data | 左摇杆 左右 |
| 8 | 0x00 | data | 左摇杆 上下 |

### 按键位定义

**字节 3（`btn1`）** —— 手柄原始数据中 **0 = 按下**：

| bit0 | bit1 | bit2 | bit3 | bit4 | bit5 | bit6 | bit7 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| SLCT | JOYR | JOYL | STRT | **UP** | **RIGHT** | **DOWN** | **LEFT** |

**字节 4（`btn2`）**：

| bit0 | bit1 | bit2 | bit3 | bit4 | bit5 | bit6 | bit7 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| L2 | R2 | L1 | R1 | △ | **○** | × | **□** |

### 取反处理

```c
st->btn1 = (uint8_t)(~ps2_rx[3]);      /* 0=按下 → 1=按下 */
st->btn2 = (uint8_t)(~ps2_rx[4]);
```

**为什么取反**：手柄硬件约定"按下 = 接地 = 低电平 = 0"，但对写逻辑的人"1 = 按下"更直观（`if (btn & UP)` 读起来就是"如果按了上"）。

**在边界处统一转换，内部保持一致** —— 整个工程后面再也不用考虑这个反逻辑。

外面的 `(uint8_t)` 强转是必需的：`~` 作用于 `int` 会得到 `0xFFFFFF10` 这样的值，必须截断到 8 位。

## 软件模拟 SPI 时序

### 为什么不用硬件 SPI

| 方案 | 问题 |
| --- | --- |
| **硬件 SPI 外设** | 需要额外配置，且 PS2 的时钟时序（半周期 16µs）与 STM32 SPI 的最小分频不完全匹配；用 DMA 更复杂 |
| **软件模拟（采用）** | 完全可控，时序想怎么调就怎么调，代码直观、易于教学和排查 |

### 单字节传输

```c
static uint8_t ps2_transfer(uint8_t cmd)
{
    uint8_t mask;
    uint8_t res = 0;                    /* ⚠️ 必须初始化，否则是随机垃圾值 */

    for (mask = 0x01; mask != 0x00; mask <<= 1) {
        /* 1. 输出命令位 */
        if (cmd & mask) { CMD_H(); } else { CMD_L(); }

        /* 2. 拉低时钟，等待从机 */
        CLK_L();
        ps2_delay_us(16);

        /* 3. 在时钟低电平期间读回数据位 */
        if (PS2_DAT()) { res |= mask; }

        /* 4. 拉高时钟，完成这一位 */
        CLK_H();
        ps2_delay_us(16);
    }
    return res;
}
```

**逐句解释**：

| 语句 | 含义 |
| --- | --- |
| `for (mask = 0x01; mask != 0x00; mask <<= 1)` | `mask` 依次为 `1,2,4,...,128,0`。当 mask 是 128 再左移会溢出成 0，循环结束 —— **正好 8 次 = 一个字节** |
| `cmd & mask` | 按位与，只留当前那一位，结果非 0 表示该位为 1 |
| `res \|= mask` | 读到的位为 1 时，把它"点亮"到结果的对应位置 |
| `16us` | 手册规定时钟半周期约 16µs（对应约 31kHz） |
| **LSB 先行** | 从 `0x01` 开始，先发最低位，这是 PS2 协议的规定 |

### 微秒延时：为什么用 TIM1 而不是 DWT

| 方案 | 问题 |
| --- | --- |
| **`HAL_Delay()`** | 精度只有 1ms，**差太远** |
| **`DWT->CYCCNT`** | DWT 属于 Cortex-M3 的**调试组件**，只有在调试器连接时才保证工作。**没插调试器时 CYCCNT 可能恒为 0**，导致 `while` 条件永远成立 → **程序直接卡死** |
| **`for` 空循环** | 受编译器优化影响，`-O0` 和 `-O3` 下延时完全不同，不可靠 |
| **TIM1 自由计数器（采用）** | TIM1 在本工程中完全空闲（电机用 TIM2/TIM3）。**普通外设，任何情况下都可靠** |

实现：

```c
static void ps2_timer_init(void)
{
    __HAL_RCC_TIM1_CLK_ENABLE();    /* 1. 开时钟，否则外设不工作 */
    TIM1->PSC = 71;                 /* 2. 72MHz / (71+1) = 1MHz → 1 计数 = 1µs */
    TIM1->ARR = 0xFFFF;             /* 3. 16 位最大周期，约 65.5ms 溢出一次 */
    TIM1->EGR = TIM_EGR_UG;         /* 4. 产生更新事件，使 PSC 立即生效 */
    TIM1->SR  = 0;                  /* 5. 清更新标志 */
    TIM1->CR1 = TIM_CR1_CEN;        /* 6. 启动计数 */
}

static void ps2_delay_us(uint32_t us)
{
    uint32_t start = TIM1->CNT;
    while (((TIM1->CNT - start) & 0xFFFFu) < us) { }
}
```

**`& 0xFFFF` 的作用**：CNT 是 16 位、会从 65535 回绕到 0。直接相减会得到负数（无符号下变成巨大值），**加上掩码就能正确处理回绕**。

### 时间预算

| 项目 | 时间 |
| --- | --- |
| 1 位 | 16µs × 2 = 32µs（含 GPIO 操作开销约 35µs） |
| 1 字节（8 位） | 约 280µs |
| **9 字节一次完整通信** | **约 2.5ms** |
| 扫描周期 | 10ms |
| **余量** | **7.5ms**（充足） |

## 数据有效性校验（两道门）

```c
if (ps2_rx[1] == 0x00 || ps2_rx[1] == 0xFF) {
    return 0;                       /* 第 1 层：模式字节不合理 */
}
if (ps2_rx[2] != 0x5A) {
    return 0;                       /* 第 2 层：固定字节不匹配 */
}
```

| 校验 | 挡住什么 |
| --- | --- |
| **第 1 层**（模式字节 ≠ 0x00/0xFF） | 接收器没插好/没上电。此时 DATA 线被上拉就是全 1（0xFF），被拉低就是 0x00 |
| **第 2 层**（0x5A） | **字节错位**和偶发噪声帧。通信中途被打断时 9 个字节会整体挪位，此时 `ps2_rx[2]` 就不是 0x5A |

**第 2 层是官方例程没有的，我们额外加的。** 少了这一层，垃圾数据会直接进入控制链路，表现为"手柄没动、电机却一直转"。

**返回值设计**：`PS2_Scan()` 返回 1=有效、0=无效，由**调用者**决定怎么处理（停车、重试、报警）。驱动层只负责如实上报，不擅自做主。

## 急停与安全逻辑

### SELECT / START 的功能

| 按键 | 代码 | 行为 |
| --- | --- | --- |
| **SELECT** | `if (btn1 & PS2_BTN_SELECT) g_estop = 1;` | **紧急停车**，并**锁存** |
| **START** | `if (btn1 & PS2_BTN_START) { g_estop = 0; HAL_Delay(200); }` | **解除急停锁存** |

**"锁存"的含义**：按下 SELECT 后即使松手，`g_estop` 仍然保持 1，控制循环里 `if (g_estop) chassis_stop();` 会让四个轮子一直输出 0。**必须按 START 才能恢复。**

**为什么不用"按住才停"**：松手瞬间车会突然窜出去，更危险。工业急停按钮也是这种"按下锁死、旋转复位"的设计。

### 手柄掉线保护（失效安全）

```c
if (!PS2_Scan(&g_ps2)) {
    chassis_stop();         /* 立刻停车 */
    g_estop = 1;            /* 并锁存急停 */
}
```

**"失效安全（fail-safe）"设计**：信号丢失（跑出范围、没电、强干扰）时，**默认行为必须是停车**，而不是保持上一次的速度继续冲。

如果这里什么都不做，`g_ps2` 里还是上一帧的旧数据，机器人会"自己一直往前冲" —— 这是最危险的失效模式。

### 上电需要先按 START

上电后第一次 `PS2_Scan()` 有可能失败（接收器/手柄还没就绪），此时会锁存急停。

**因此操作流程是**：上电 → **先按一次 START 键** → 再用手柄遥控。

### 已知改进点

`START` 分支里的 `HAL_Delay(200)` 是阻塞延时，200ms 内主循环不扫描手柄，可能导致下一次 `PS2_Scan()` 返回无效而**重新锁存急停**（表现为"按一次 START 解不开，要按好几次"）。

**改进方向**：把阻塞延时换成时间戳保护窗口 —— 记录按下时刻，在 200ms 内忽略掉线判定，而不是死等。

## 官方参考代码对照

本项目 `ps2.c` 的结构参考了塔克创新（XTARK）的 `ax_ps2.c`，并做了以下改进：

| 项目 | 官方 `ax_ps2.c` | 本项目 `ps2.c` |
| --- | --- | --- |
| 引脚 | PA4=DAT, PA5=CMD, PA6=CS, PA7=CLK | **相同** |
| 命令数组 | `{0x01,0x42,0,...,0}` 9 字节 | **相同** |
| 位循环 | `for(ref=0x01; ref>0x00; ref<<=1)` | **相同** |
| 半周期延时 | `AX_Delayus(16)` | `ps2_delay_us(16)`（TIM1） |
| 采样时刻 | `CLK_L()` → 延时 → 读 → `CLK_H()` | **相同** |
| 取反 | `btn1 = ~PS2_data[3]` | `(uint8_t)(~ps2_rx[3])`（显式截断） |
| **0x5A 校验** | **无** | **✅ 新增** |
| **掉线返回值** | **无**（void 函数） | **✅ 返回 1/0** |
| 微秒延时 | 独立 `ax_delay.c` | 内置 TIM1 计数器 |
